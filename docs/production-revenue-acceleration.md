# 正式版 C5 營收加速

2026-10-28 使用者明確決定將開發候選 C5 加入正式版。版本為 `rules-v6-revenue-acceleration-top20`，保留 v5 全部財務、KD、MACD、法人及成交量門檻與排序、最多二十檔，不足不補。文字研究模組沒有併入。

## 條件與來源

若最新可用營收月份為 m：

```text
current_growth = sum(R[m], R[m-1], R[m-2]) / sum(同三個月去年營收) - 1
previous_growth = sum(R[m-3], R[m-4], R[m-5]) / sum(同三個月去年營收) - 1
C5 通過：current_growth - previous_growth > 0
```

原本的 current_growth > 0 仍須通過；加速恰好等於零不通過。採三月合計後的年增率，不能平均三個月的個別年增率，也不是單月月增率。

沿用 MOPS `nas/t21/sii` 與 `nas/t21/otc` 月營收表，使用當月營收及表內去年同月營收。每市場抓前七個已結束月份、兩類表，共二十八張月表；沒有逐股查詢、併發抓取或新增資料供應商。先取最近三月完整窗口；上一個月尚未有資料時，沿用原版最多延後一個月的規則。窗口一旦選定，不會為了前段資料不全而向更早月份尋找可通過的加速數值。

六個月及其去年同期需完整，兩段去年合計基數需為正。缺值、非有限數值或同一公司月份的衝突紀錄保持未知，排除該公司，不補零。若整個市場沒有可計算的加速資料，推薦建構會報來源錯誤，避免誤報為零檔合格。

## 保存與生效

- 財務快照保存兩段成長率、加速幅度、六個來源月份與當年／去年營收及取得日；取得日不冒充歷史公告日。
- 推薦診斷與 signals 保存 `revenue_yoy_prev_3m`、`revenue_growth_acceleration`，候選與 signals 另保存六個來源月份。加速從兩段比率重算，不直接相信輸入的加速欄位。
- 生效點是 main 合併後首次新建的推薦。已存在的 v5 推薦與報告維持原樣，同日重跑不改名單，也不重送。
- 若當天已有不含 C5 的財務快照，但還沒有推薦，當天正常重新觀測的快照另存 `financials/YYYY-MM-DD-c5.json.gz`，保留原快照。歷史日期缺 C5 欄位則明確拒絕，不用今天資料回寫正式歷史推薦。
- 隔離測試使用同一規則；舊快照不含新欄位時，依既有授權使用執行日快照並揭露真實日期，輸出仍只在測試範圍。
